# Hallmark core rules

These are outcome constraints, not a template.

1. **Existing product wins.** Reuse its tokens, typography, components, routes,
   content model, and interaction language. Do not impose a separate Hallmark
   system on a mature product.
2. **Content determines structure.** Choose hierarchy and composition from the
   user's task and information shape. Avoid common AI page rhythms when they do
   not serve the content, but do not force novelty for its own sake.
3. **Copy stays honest.** Never invent metrics, testimonials, logos, case-study
   counts, awards, integrations, or product capabilities. Use supplied content,
   clearly labelled placeholders, or a structure that does not need proof.
4. **Tokens stay coherent.** Reference existing semantic tokens. On a greenfield
   surface, define a small semantic set once; avoid one-off colors, fonts,
   radii, shadows, spacing values, and animation timings scattered through code.
5. **Assets stay real.** Use user-supplied or licensed assets. Do not fabricate
   browser chrome, device frames, dashboards, or screenshots to imply a product
   exists. A clearly labelled placeholder is better than false evidence.
6. **Interaction stays legible.** Prefer native semantics, visible focus, useful
   labels, adequate targets, deterministic state changes, and error recovery.
   Animation must communicate state or hierarchy and honor reduced motion.
7. **Responsive means observed.** Prevent overflow and broken reading order, but
   do not claim responsive or accessibility success from source inspection
   alone. Render and test when the environment permits it.
8. **Verification stays truthful.** Static checks catch patterns, not taste.
   Report what ran, what was visually inspected, and what remains unverified.
