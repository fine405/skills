# Reusable Theme Module Template

Create `references/theme-<slug>.md` from this contract when the user asks to
add a reusable theme family. Keep it independent of named brands, rendering
styles, platform sizes, safe zones, store rules, and packaging.

## Required sections

```markdown
# Theme Module: <Human Name>

## Aliases and triggers
List phrases, translations, and request patterns that select this module.
Distinguish nearby themes that must not be substituted silently.

## Theme scope
Define what may vary and the emotional or semantic range the family covers.

## Identity invariant contract
State which source-icon properties must remain stable across variants.

## Semantic cue palette
Map subthemes to optional materials, objects, construction, marks, motion, or
environmental cues. Provide choices, not a single mandatory visual stereotype.

## Transformation modes
Explain how surface substitution, structural analogy, and controlled
accessories apply to this theme family.

## Intensity scale
Define visible differences among subtle, balanced, and expressive variants.

## Style combination
Explain how this theme combines with an independently selected rendering style
without taking over that style's role.

## Prompt additions
Provide a compact clause with placeholders for source identity and selected
subtheme.

## Negative constraints
List identity drift, semantic confusion, stereotypes, and common visual
failures specific to the theme.

## Theme-specific evaluation
Add checks not already covered by the main theme quality gate.

## Compatibility notes
Explain how to simplify cues for small sizes, monochrome variants, or layered
assets without repeating platform specifications.
```

## Authoring rules

- Derive cues from broad, observable associations or user-owned references; do
  not cite or copy private prompts, proprietary skill text, or a specific
  brand's campaign.
- Offer several culturally responsible cue families rather than one cliché.
- Make the theme usable with flat, tactile, translucent, reflective, and future
  rendering styles.
- Keep one dominant semantic cue per generated variant.
- Link stable catalog entries directly from `SKILL.md`; preserve filename
  discovery for additional modules.
