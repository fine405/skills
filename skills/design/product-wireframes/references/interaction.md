# 交互与动效

仅应用需求中已有的模式。以下默认值用于演示，可按项目规范调整。

## 页面与状态

把状态按归属分开：当前页面、页面内部选择、弹层，以及演示控制。共用数据可以影响多个页面；页面的阅读位置各自保留。

页面栈中的每一层可保存 `page`、`selection`、`expanded`、`scroll` 和返回焦点。跳转前保存，返回时恢复。不同页面不应因为共用了组件而意外共用同一个筛选值。

| 模式 | 需要表达的行为 | 常见误差 |
|---|---|---|
| 进入与返回 | 进入方式、返回位置、应恢复的状态 | 返回重置日期或滚动位置 |
| 日期 | 日期来源、可选范围、确认与取消 | 把预览日期当已提交日期；滑动时误触行按钮 |
| 筛选 | 选中反馈、列表变化、结果范围 | 筛选列表时误改总分或其他汇总值 |
| 展开 | 展开范围、折叠后的位置 | 内容覆盖下方区域，或页面突然跳走 |
| 弹层 | 背景、关闭方式、内部滚动、返回焦点 | 背景仍能点击；Tab 跑到背景；关闭后丢焦点 |
| 趋势 | 时间范围、选点、对应读数 | 图表切换了，读数还停在旧数据 |
| 编辑 | 保存与取消的差别、关联数据刷新 | 点取消仍改数据；只更新一个可见位置 |
| 空与不完整 | 用户能理解的状态、仍然可用的操作 | 把未知数据画成零，或用正常骨架掩盖状态 |

从需求中决定上述具体规则。例如默认日期、筛选是否影响汇总、跨页是否继承选择，不能从模板或上一项目照搬。

不必实现生产算法。用少量确定的示例数据表达规则，保证同一场景的显示一致。正式算法、计算依据和外部依赖仍由 PRD 定义。

## 动效表达

动效解释操作结果。不要让内容无故循环漂浮或闪动。下表时长只是起点。

| 动作 | 推荐表现 | 常用时长 |
|---|---|---|
| 前进与返回 | 水平移动，方向相反 | 220–300 ms |
| 弹层开关 | 遮罩淡入淡出，面板从底部进入 | 180–280 ms |
| 展开与折叠 | 高度变化，推开或收回下方内容 | 180–260 ms |
| 日期切换 | 仅内容区随方向移动并淡入 | 160–240 ms |
| 筛选重排 | 保留项移动，离开项淡出 | 160–240 ms |
| 趋势选点 | 选中标记和读数更新 | 100–180 ms |

- 支持 `prefers-reduced-motion: reduce`，保留结果和操作，减少或取消移动。
- 每次动画结束后清理旧节点；新操作可以接替旧动画，不能排成长队。
- 展开优先使用 CSS grid 行或测量实际高度，避免写死高度导致截断。
- 筛选需要重排时可使用前后位置差值动画；无需重排的列表只更新内容。
- `animation.finished` 可能因取消而拒绝；处理取消，避免未处理错误。
- 只有需求需要手势时才增加手势。横向操作必须与纵向滚动区分，拖动结束后抑制误点击。

## 演示控制

多步流程可增加手动触发的“播放流程”，放在画面外。播放应走同一套交互函数，不另造一套演示页面。

提供停止和重置。用户开始操作时停止自动流程，避免旧定时步骤覆盖用户选择。不自动播放，不把演示控制加入产品需求。

## 检查方式

为本次需求列出少量可观察的结果，例如“从明细返回后，筛选仍为已选项，列表停在原位置”。使用浏览器操作核对结果，不只检查代码中存在某个函数。

截图选择稳定的最终状态；动效本身要实际播放查看。先修正问题，再重新截取受影响的图。
