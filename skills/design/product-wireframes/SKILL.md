# 产品线框稿

让产品同事直接看懂：页面有什么、操作后发生什么、返回后保留什么。用可运行的低保真原型解释已确认需求。

本 skill 自带流程和模板，不依赖其他设计 skill。默认交付可离线打开的单文件 HTML；需要静态评审材料时，从同一 HTML 截取少量关键图。用户只要静态稿时，按该范围交付。

## 1. 明确本次要说明的体验

读取用户提供的需求、页面和适用项目说明。引用聊天或远端文档时，先实际读取。

用一段简短说明或一张小表确定：

- **页面**：主页面、明细页、弹层，以及入口和返回关系。
- **操作**：首版需要演示的点击、手势、展开、切换和编辑。
- **状态**：默认状态及会影响理解的空、部分数据、错误或边界状态。
- **约束**：已确认的默认值、数据规则、首版范围和设备形态。

已有信息足够时直接制作，不要求用户重复确认。只有缺失信息会改变范围或关键行为时才提问。细节可采用合理默认，并说明影响结果的假设。

模板中的操作只是实现示例，不能成为新增需求。未确定的规则标为待确认，不用原型替用户作业务决策。

## 2. 选画布和保真度

- 手机功能默认使用正视的二维手机框；桌面功能使用对应的桌面布局。按任务选择单屏、并排对照或连续流程。
- 多页面优先在同一画面里真实跳转；需要比较两项功能时再并排展示。不要把所有页面同时堆在画布上。
- 用细线、灰阶、留白和清晰的层级组织内容。避免为线框增加品牌装饰、透视或立体效果。
- 保留真实的页面名、动作、日期、筛选和状态标签。正文、图片、名单和次要数值可用骨架代替。
- 骨架表示被省略的内容，默认静止；仅在需求包含加载状态时演示加载动画。
- 对理解交互有必要的数值可以保留，但必须使用示例数据。演示说明、播放、重置和场景切换放在产品画面外。

## 3. 做成可运行的原型

先阅读 [交互与动效](references/interaction.md) 中本次涉及的规则。

可以复制 [手机骨架模板](assets/wireframe-starter.html) 到交付目录后改造；不要直接修改已安装的模板。它只提供页面切换、返回恢复、展开、弹层和流程播放的最小示例。先删除需求不需要的示例，再补本次内容。桌面或特殊形态不必沿用手机外壳。

默认用 HTML/CSS 绘制结构，内联 SVG 绘制图标和简单图表，原生 JavaScript 管理交互。使用 CSS 过渡或 Web Animations API 实现动效。已有项目或用户指定工具时沿用其约束。

- 共用外观和交互只维护一套；不同页面分别保存自己的日期、筛选、展开和滚动状态。
- 使用明确的页面栈和弹层状态，避免靠页面外观猜当前状态。
- 演示数据保存在内存里；编辑只改变本次演示。不要连接真实业务写入。
- 输出尽量不依赖构建、外部字体、CDN、远端图片或外部脚本，让同事收到文件就能打开。
- 按用户语言制作，不因为模板有某种功能就强制加入双语、日期、趋势或编辑功能。

## 4. 检查真实操作

使用当前环境可用的浏览器工具。已有 Playwright 环境可用于批量操作和截图，不要求另装特定浏览器插件。

先实际跑通需求中的主要路径，再检查相关边界：

- 进入、操作、返回后的状态是否符合需求；弹层不会让背景误操作。
- 连续点击、快速切换、取消和重置是否留下重复画面或旧状态。
- 图表、筛选、日期和编辑是否只改变各自应改变的内容。
- 目标视口没有截断关键操作；长内容可滚动。
- 键盘可访问主要操作；弹层关闭后焦点返回；减弱动态效果生效。
- 控制台没有未处理错误；离线交付文件不依赖网络资源。

截图后必须查看实际画面。自动检查通过不能替代视觉检查。没有浏览器时可做文件和语法检查，但明确说明交互和截图未验证。

只运行与本次原型有关的检查。无需为线框改动构建真实 App，也不在业务仓库中增加长期测试套件。

## 5. 交付与文档组织

交付一个明确入口，如 `feature-wireframes.html`。需要放入 PRD 时，通常选 2–4 张能解释关键决策的图；简单功能可以更少。

- 正文放页面概览或核心路径；附录放必要的展开、弹层或返回状态。
- 静态图从最终 HTML 截取，并核对截图与交互版本一致。不要分别维护两套画面。
- 保留一个完整交互入口，避免在正文重复解释附录细则。
- 简短说明已覆盖的路径、检查结果和未实现的部分。演示不能作为生产功能已经实现的证据。
- `localhost` 只供本机预览；交付实际 HTML 文件或用户已授权的共享地址。

仅在用户要求写入飞书时，读取 [飞书接入](references/feishu.md)。未接入飞书不影响本地交付。
