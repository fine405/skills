# Define：视觉手段、组合与提示词

在需要强化主视觉、材质、空间或运动时读取。原文明确提出图像生成结合 shader/3D，以及两类视频应用；下面的媒介选择表、实时交互判断和验证细节是为落地补充的工程建议。示例提示词按原文思路重新表述，不绑定模型版本或服务商。

## 选择能实现目标的媒介

| 需要表达的效果 | 可选手段 | 选择时关注 |
| --- | --- | --- |
| 独特插画、摄影、纹理、固定视角的物体 | 图像生成或现有图片 | 构图、留白、裁切，以及与页面字体/配色是否一致 |
| 随指针、滚动或状态变化的扭曲、粒子、材质和光效 | shader，可结合图片纹理或 3D | 实际输入如何驱动效果、运行成本、文字可读性与回退 |
| 用户可改变视角、旋转物体、探索空间或操控部件 | 实时 3D，可配合 shader 与图像纹理 | 是否真正需要几何、相机与实时状态；静态等距图不是实时 3D |
| 固定镜头下复杂的运动、折射、焦散和形变 | 生成视频或预渲染片段 | 能否循环、是否可嵌入背景、素材体积，以及用户可控的范围 |
| 产品状态之间的连续展示 | 关键帧视频串联，或需要自由操作时使用实时 3D | 是否只需沿预设路径播放、拖动或滚动，还是需要任意改变状态 |
| 简单的界面反馈与层级过渡 | 现有 CSS/平台动画能力 | 普通 UI 动效无需一律升级成视频或 3D |

先确定职责，再组合媒介。例如：生成图定义物体外观，图片作为纹理进入 3D 场景，shader 实现响应指针的光效；或生成视频承担复杂背景运动，真实 UI 保持可读、可操作。不要因为代码容易写，就只使用默认渐变和几何形状；也不要假定图像/视频天然优于代码。

## 图片 + shader / 3D：强化已有方向

> 当前 [区域] 的视觉身份还不够鲜明。围绕既定的 [意象、材质、情绪] 生成有辨识度的图片，并评估它与 shader 或 3D 效果的组合。明确图片负责什么、实时效果负责什么，以及效果如何响应用户行为。选择能突出产品内容的方案，保持原有信息层级，并在实际页面中检查静态构图、关键帧和运动过程。

先完成一处能代表效果的局部，确认整合效果后再扩展。若用户只需固定构图，不必为一张看起来像 3D 的图建立实时场景；若用户要求可交互的镜头、光照或物体状态，则不能只交付一段视觉上类似的影片。

## 循环视频：把片段作为界面中的动态图形

原文方法：生成带纯色背景的循环片段，随后用色键或视频抠像去背景，再叠入界面。

> 把 [主视觉物体] 做成缓慢变化的循环动画，让它 [分裂、旋转或其他符合方向的运动]。为抠像准备适合的纯色背景；根据物体边缘、透明材质和运动复杂度，选择色键或视频抠像。将结果放回页面，检查循环接缝、边缘、光影与文字的关系。

**玻璃示例的关键顺序**：先在实际页面背景颜色上生成玻璃运动，使折射与光影呈现出对该背景的反应，再用视频抠像移除背景。简单绿幕方案可能把不希望出现的颜色带入透明材质，不能不加判断地套用。

> 为当前玻璃晶体生成分裂后缓慢旋转的循环片段。先使用页面实际背景色生成折射、焦散与光影，再进行视频抠像并合成回原页面。检查透明边缘和不同帧的连续性；如果透明材质无法可靠抠出，说明限制并调整合成方法，不声称效果已经成立。

工程补充：预先烘焙的折射不能动态折射任意 DOM 背景。页面背景、主题、物体位置或相机变化后需重新核验；需要真正随环境变化的效果时评估实时 shader/3D。根据目标浏览器验证透明视频或其他合成格式，不假定普通视频天然支持透明度。

## 关键帧转场：让动作或滚动控制进度

原文包含两种驱动方式：点击/导航时播放过渡；滚动/滑动时逐帧控制。连续转场的核心是共用边界帧，而非独立生成几段不相干的片段。

1. 规划状态与运动方向，使画面动作呼应手势。
2. 用图像生成得到初始帧；工具支持时约束每段首尾关键帧。
3. 生成第一段转场，把实际尾帧作为下一段起点，继续到最终状态。
4. 将片段播放或帧进度映射到用户动作，逐段检查边界衔接。

> 做一个旅行箱展示原型：箱子先悬在空中，然后落地并打开，最后物品从上方落入箱内。先生成首帧，按状态逐段生成视频，用上一段真实尾帧衔接下一段。让向下滚动推动这些垂直动作，反向滚动能回看先前状态。选择支持所需关键帧约束、物体一致性和运动质量的可用工具，在浏览器中逐帧核验接缝与滚动控制。

反向滚动、解码/拖动表现等是工程补充，不应由单张截图推断。视频表达预设状态变化，不负责代替真实业务状态或操作控件。

## 工具与资源接入

- 检查现有的内置图像/视频能力，必要时明确要求使用；不要假设编码代理会主动调用这些工具。
- 在已有授权下，也可使用其他本地工具或 API；视频聚合服务可减少多模型接入工作，但不是硬依赖。实施时依据当时官方能力确认关键帧、抠像与输出格式，避免写死文章中的模型名称。
- 不把特定订阅的计费方式、免费额度或服务功能固化成保证。需要外部服务时先核实当前工具和授权，不因为示例里有 API key 就要求用户粘贴密钥。
- 确实需要开发凭据时使用已有凭据存储；若采用本地环境文件，确保被 Git 忽略且不进入前端构建或交付产物。沿用用户的费用限制，不把密钥写入提示词模板、截图、仓库或客户端。

## 在整合后的页面验证

检查关键帧与实际播放、去背景边缘、循环接缝、滚动前后与反向移动、相关尺寸和主题；实时效果另外检查输入响应与视角变化。确保静态回退和减少动态效果设置下仍能理解内容，视频/画布不遮挡按钮与键盘操作。报告实际验证的部分与尚未验证的性能，不以“视觉更丰富”自动判定设计更好。
