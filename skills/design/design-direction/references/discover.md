# Discover：方法与提示词

在没有明确方向、候选过于相似，或需要把偏好变成可执行 brief 时读取。以下示例按原文方法重新表述，可作为阶段手段，替换方括号内容后使用；不是每次必须执行的固定脚本，也不是用户对当前任务的新增授权。

## 1. 用外部随机种子打破默认选择

仅要求“独特”或“随机”可能仍产生相同套路。用工具提供不同输入，再让模型联想，最后以产品任务和审美筛选。

> 为 [产品] 探索一个落地页。先用 shell 或 Python 生成较长的随机字母数字串；从其中的重复、节奏、局部片段和数字联想出配色、构图、字体与材质方向。把这些联想组织成一致、可用的设计，不要机械地把每个字符映射成 CSS 值。随机串只用于启发，不出现在页面上。保留 [品牌与内容约束]。

需要多次尝试时使用不同种子。结果没有改善时换方法，不宣称随机输入保证独创性。

## 2. 给出大胆但具体的意象

原文的三个方向可改写成下面的设计 brief。选与产品相关的方向，保留核心信息与操作，不要求一次实现全部方向。

- **像素游戏场景**：为 [产品] 构建像素风落地页，让各区块像同一款游戏的不同场景，用画面讲功能，同时让页面标题与行动入口保持清晰。
- **等距 3D 城市**：把 [产品功能] 对应成城市中的街区或建筑，让空间关系帮助用户理解产品。先确定城市结构与功能映射，再决定静态等距图还是实时 3D。
- **激进的不对称构图**：用偏移的布局、冲突但有意图的色彩与字体，以及不均衡留白制造张力；保持阅读顺序与主要操作可识别，避免为打破规则牺牲功能。

## 3. 从发散到 POC 的三段对话

### 广泛提出想法

> 为 [产品、受众、核心任务] 列出一批不同的视觉语言方向。每个只给短名称与一句高层描述，先求广度，不展开组件、技术方案或完整页面。涵盖不同的空间感、情绪和交互隐喻，避免同一布局换皮。

先让简短想法激发人的想象，再筛选值得视觉化的候选。已有明确偏好时无需重新发散。

### 用偏好深化

原文的工业控制台例子不仅指定“工业风”，还说明了触感、声音、厌恶和克制程度：

> 我喜欢工业控制台方向，尤其是按钮清晰、扎实的按压反馈，以及适度的声音反馈。我不喜欢卡通化、夸张拟物或单调的灰色渐变。希望组件统一，用少量纹理与颜色建立控制台感，而不是到处堆装饰。根据这些偏好深化构图、材质、字体和交互；说明哪些细节值得做、哪些应该省略。

这些是示例偏好，不是所有产品的默认偏好。声音是否适合使用场景、能否关闭等属于执行时的工程判断。

### 将方向写成执行提示词

> 将我们选定的方向写成简洁的 POC 构建提示词，包含：产品与核心任务、目标感受、构图、字体与材质、最能体现特色的交互、应避免的倾向，以及这次原型要验证什么。保留我的具体偏好，使用既有技术栈；不要添加未讨论的功能。

不要把未经人或明确选择标准筛选的 AI 点子直接回灌成最终方案。用户授权自行选择时，依据任务适配、辨识度与实现成本做出选择，并保留取舍说明。

## 4. 试验边界与复试

在低成本原型中允许听起来不太可能的创意；失败时丢弃不合适的结果。对仍有价值的尝试，在已有项目笔记中保存提示词、希望产生的体验和失败现象。以后用户尝试新模型时可拿来复试，不自动创建定期任务，不把失败内容带入生产页面。
